# Rate90 前后端开发记录（2026-11-22）

> 本文保存 2026 年 11 月 22 日的样本、设计目标和验证结果。当前版本的运行方式和页面行为见[项目说明](../README.md)。

本次验证使用评分版本 `rate90-1.0.1`。

Rate90 帮用户在不知道赛果的情况下挑一场足球回放。当前已有可用的静态站、赛程采集器和固定评分算法。下一步的重点是把已取得的比赛数据接到新版列表和详情，并完成咪咕单场跳转与「看过」记录。

## 二、后端、评分与数据

**数据路径**　BSD 赛程和详情 → SQLite 保存比赛及评分依据 → 按常规时间聚合射门、机会与攻势 → 生成评分 → 先写比赛日详情和预览，再原子替换静态索引。前端初始列表读取索引，打开比赛时按需加载比赛日文件。

| 接手入口 | 用途 |
|---|---|
| [BSD 客户端](../server/bsd.mjs)、[逐脚统计](../server/shot-profile.mjs)、[评分函数](../server/recommend.mjs) | `summarize` 归一化供应商数据，`rateMatch` 计算分数，`formatFeed` 生成单日输出。 |
| [采集队列](../server/collector.mjs)、[常驻进程](../scripts/collect.mjs) | 北京时间每日 12:00 刷赛程。开球后 **125 分钟**首查（90 分钟比赛＋上下半场各 10 分钟补时＋15 分钟中场），仍在赛则每 15 分钟复查。常规首采后 6 小时校正，资料仍不足则在首采后 24 小时补查。 |
| [发布逻辑](../server/publish-collected.mjs)、[比赛接口](../server/matches-api.mjs) | 默认读取本地已发布数据；当日有固定样本时可返回样本。显式指定 `source=live` 才请求 BSD。API 看球日按北京时间前一日 12:00 至当日 12:00 划分；列表日期取赛程日期，关联时使用比赛 ID。 |
| [本轮采集与校验](../scripts/fetch-test-round.mjs)、[离线样本构建](../scripts/build-offline-sample.mjs) | 前者保留供应商原始响应；后者读取 `data/bsd-sample.json` 生成 12 场固定样本。重建固定样本不会把 47 场导入静态站。 |

固定评分按 **进攻威胁 25%、进攻节奏 15%、看点持续性 20%、双方对抗 15%、射门与扑救看点 10%、比赛悬念 15%** 计算。常规时间包含补时。乌龙球计入比分进程和进球看点，射门次数、射正和 xG 只统计真实进攻射门；普通射门缺 xG 时保留缺失。产品移除页面比分后，后端仍用进球进程计算悬念。[评分公式与口径](matches-api.md)

**本轮样本**　北京时间 2026-11-22 19:50 完成抓取。英超第 11 轮、西甲第 13 轮、意甲第 12 轮、德甲第 10 轮、法甲第 11 轮、欧冠第 4 轮共 66 场。当时 47 场完赛、1 场进行中、18 场未开赛。新版算法的 47 场共有 1,331 次实际射门，全部有 xG。乌龙球修复使 3 场恢复评分，其余 44 场评分一致。

| 真实数据与覆盖 | 前端可用内容 |
|---|---|
| 47/47 场有确认首发、两队阵型及教练 | `lineups.{home,away}.players` 各 11 人；`formation` 为本场开场阵型；教练姓名取 `home_coach.name`、`away_coach.name`。 |
| 47/47 场有可生成的 90 格攻势序列 | `momentum` 中正值为主队攻势、负值为客队攻势。按分钟绘图，缺测留空。 |
| 47/47 场有换人记录 | `incidents` 含换人及牌，时间取 `minute` 与 `added_time`。换人使用 `player_in/out`；已观察到 `yellow`、`yellowRed`、`red` 三种牌型。 |
| 7/47 场有双方跑动距离，本样本均为英超 | `live_stats.{home,away}.distance_covered` 返回如 `115.9 km`。有值才展示，缺测留空。 |

复算使用的轮次目录为 `data/round-tests/pl11-ll13-sa12-bl10-l111-cl4/`。其中 `events/<BSD ID>.json` 保存逐场响应，`manifest.json` 记录抓取时的评分，运行离线校验可生成 `coverage.json`。原始响应由运行采集的部署方保存。

### 20 个风格标签的首版试算

规则按常规时间统计。关键机会沿用评分算法：一脚射门满足进球、中柱、xG ≥ 0.15 或 xGOT ≥ 0.35 中任一条件，计一次。时段为六个 15 分钟段。以下是设计阈值，47 场中 44 场至少命中一项，单场最多 11 项。现有 `viewingProfile` 仍使用旧阈值及 `slice(0, 2)`；接手时需替换规则和截断逻辑。

| 类别 | 标签 | 首版触发条件 |
|---|---|---|
| 场面与节奏 | 双方对攻 | 双方各 ≥3 次关键机会，较少一方占比 ≥1/3，至少 2 段双方均有机会。 |
| 场面与节奏 | 单边压制 | 全场 ≥6 次关键机会，同一队占 ≥75%，且在 ≥60% 的有效攻势分钟占优。 |
| 场面与节奏 | 机会贯穿全场 | ≥7 次机会，覆盖 ≥5 段，任一段均少于总数的一半。 |
| 场面与节奏 | 机会集中 | ≥5 次机会，同一段至少占一半。 |
| 场面与节奏 | 节奏舒缓 | 射门 ≤20 脚且关键机会 ≤5 次。 |
| 进攻方式 | 频繁传中 | 两队合计传中尝试 ≥40 次。 |
| 进攻方式 | 长传频繁 | 长传尝试 ≥100 次且占全部传球 ≥12%。 |
| 进攻方式 | 盘带频繁 | 合计过人尝试 ≥35 次。 |
| 进攻方式 | 远射频繁 | 禁区外射门 ≥10 脚且占全部射门 ≥35%。 |
| 进攻方式 | 禁区强攻 | 禁区内射门 ≥20 脚且占全部射门 ≥75%。 |
| 球权与争夺 | 拼抢密集 | 合计抢断尝试 ≥40 次。 |
| 球权与争夺 | 高空争顶 | 空中对抗 ≥35 次。以双方一致的争顶总次数计，每次争顶只计一次。 |
| 球权与争夺 | 拦截频繁 | 合计拦截 ≥24 次。 |
| 球权与争夺 | 控球主导 | 单队控球率 ≥65%。 |
| 球权与争夺 | 角球密集 | 合计角球 ≥13 次。 |
| 射门与防守 | 射门密集 | 合计射门 ≥30 脚。 |
| 射门与防守 | 门将高光 | ≥3 次高难度扑救，每脚被扑射门 xGOT ≥0.35。 |
| 射门与防守 | 封堵密集 | 合计被封堵射门 ≥10 脚。 |
| 射门与防守 | 良机频现 | ≥4 脚非点球进攻射门，每脚 xG ≥0.30。 |
| 射门与防守 | 解围频繁 | 合计解围 ≥65 次。 |

带有「成功数/尝试数」的传中、长传和过人字段取分母。提供商只给全场汇总且比赛包含加时时，需取得可分离的常规时间统计后再触发对应标签。建议前后端共用稳定的标签 ID，中文和图形使用同一份映射。

## 四、当时的开发计划与验收样例

| 顺序 | 工作 | 验收样例 |
|---|---|---|
| 1 · 后端数据 | 扩充 `collector.mjs` 的 `factKeys`。目前保存射门、事件、攻势及比分依据；新版还需要首发、教练、球队统计。定义列表、战术、比赛数据、比赛事件的输出字段。 | 用 `209642` 从原始 JSON 经存储、发布再读取，能还原双方各 11 名首发、实际阵型和教练。列表输出不含赛果，技术统计缺失时能与真实零值区分。 |
| 2 · 标签和快照 | 实现 20 项规则，生成可供静态站读取的本轮测试快照。列表只携带轻量标签信息，攻势序列随详情按需加载。 | 同场重算稳定；曼城一场命中上述四项；乌龙球样例 `209639` 为 8.3 分、xG 3.79；无标签的场次仍可展示。 |
| 3 · 卡片与详情 | 列表仅图形、详情带名称。首发默认展开，数据和事件默认折叠，删除比分相关展示。 | 从日期、轮次、全部比赛进入同一场，信息一致；手机端能辨认和展开多个标签。跑动距离选一场英超和一场缺值的比赛分别验证。 |
| 4 · 咪咕与观看记录 | 取得可核验的赛事页映射，接入独立「去看」操作和「看过」列表。 | 跳转的双方球队及比赛日期一致；重复点只记一次；刷新后仍在，删除后恢复没看过；点卡片详情不会误记。缺少单场链接时不写观看记录。 |

## 五、运行与复核

| 命令 | 用途 |
|---|---|

| `npm test` | 当时的回归结果为 **21 项通过，0 项失败**。覆盖采集时序、评分、API 与静态快照；新版标签、阵容和观看交互仍需单独验收。 |
