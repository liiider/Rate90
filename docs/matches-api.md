# Rate90 比赛接口

本地项目根目录执行 `npm.cmd run dev`，打开 `http://127.0.0.1:3000`。后端从 `.env.local` 读取 `BSD_API_TOKEN`。部署到 Vercel 时，在项目的服务端环境变量中设置同名值。

## 前端接入

| 用途 | GET 路径 |
| --- | --- |
| 当日已完赛比赛 | `/api/matches` |
| 指定看球日 | `/api/matches?date=2026-11-22` |
| 固定样本联调 | `/api/matches?date=2026-11-22&source=sample` |
| 点击揭晓后读取详情 | 在相同查询后增加 `&reveal=1`，按比赛 ID 取 `details` |

默认列表的每场比赛提供 `id`、`stage`（赛事中文名）、`kickoff`（UTC 开球时间）、`home`、`away`（供应商队名）、`recommendation` 和 `topPick`。比分、机会分布与推荐依据只在揭晓响应中返回。前端可按 `stage` 筛选。

看球日按北京时间前一天 12:00 至当天 12:00 划分，含起点。固定样本中，2026-11-22 有五大联赛 10 场，2026-11-05 有欧冠 2 场。样本按每项赛事两场选取，不能当作该日完整赛程。

`mode=live` 代表成功调用 BSD，`updatedAt` 是同步时间。部分详情调用失败时 `partial=true`，对应场次显示“资料不足”。`mode=sample` 用于样本，`capturedOn` 是采集日期。当实时源不可用且该日有样本时，同时返回 `update=upstream-unavailable`。没有可用样本时返回 HTTP 503；成功同步且当日无赛事时返回空列表。

## 推荐试算 trial-1

常规时间按六个 15 分钟时段统计。一脚射门满足任一条件就计一次关键机会：进球、中柱、xG ≥ 0.15、xGOT ≥ 0.35。一脚射门及对应扑救只计一次。

- 看全场：至少五个时段出现关键机会，双方各有至少两次。
- 看集锦：至少一次关键机会，未达到全场条件。
- 可跳过：有完整射门资料，关键机会为零。
- 资料不足：常规时间逐脚射门、分钟、逐脚 xG 或关键机会的球队归属不足。

揭晓后的 `details.processRank` 是过程推荐排名，`details.goalsOnlyRank` 是同一批比赛按常规时间总进球数的排名，同分并列。当前门槛用于比较样本，尚未经球迷观后评价校准。

## 数据源费用口径

Rate90 只采用在项目所需额度内可长期免费使用的数据源。限时免费试用、必须付费续用或会自动产生超额费用的方案均排除。
