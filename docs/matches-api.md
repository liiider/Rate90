# Rate90 比赛评分接口

比赛日接口用于本地服务。Vercel 静态站直接读取 `public/ui/data/` 下的文件。

项目根目录执行 `npm run dev`。BSD 实时请求从服务端环境变量 `BSD_API_TOKEN` 读取凭据。

| 用途 | GET 路径 |
| --- | --- |
| 当日已完赛比赛 | `/api/matches` |
| 指定看球日 | `/api/matches?date=2026-11-22` |
| 直接查询 BSD | `/api/matches?date=2026-11-22&source=live` |
| 读取固定样本 | `/api/matches?date=2026-11-22&source=sample` |
| 加载首发、技术统计及换人和牌类事件 | 在相同查询后加 `&details=1`，旧参数 `reveal=1` 也返回同一组字段 |

看球日从北京时间前一天 12:00 起，到当天 12:00 结束，包含起点。显式选择 `source=sample` 时，2026-11-22 有五大联赛 10 场，2026-11-05 有欧冠 2 场。默认查询合并发布的归档与采集器数据。

列表包含 `id`、`stage`、`kickoff`、`home`、`away`、`rating` 和 `viewing`。`viewing.styleIds` 与 `viewing.styles` 同序，分别为图标使用的稳定 ID 和中文名称。评分保留一位小数。接口在同分时按开球时间和比赛 ID 排序，缺分的场次排在最后。

`mode=live` 返回同步时间 `updatedAt`。部分详情读取失败时 `partial=true`。上游不可用时，接口优先返回本日已发布数据，再查固定样本，并标记 `update=upstream-unavailable`。两者均缺失时返回 HTTP 503。已确认的空赛日返回空列表。

## 按赛程自动采集

默认 `/api/matches` 读取已发布的比赛日。列表与详情均可离线使用。本轮归档和持续采集的记录按比赛 ID 合并，返回 `mode=stored`。显式指定 `source=live` 可用于诊断供应商接口。

| 时间（北京时间） | 操作 |
| --- | --- |
| 首次运行、之后每天 12:00 | 拉取欧冠和五大联赛今日、前两天与未来七天的赛程。逐个赛事记录成功同步的日期，失败的赛事 15 分钟后重试。 |
| 开球后 125 分钟 | 首次检查完赛状态。相同赛事、相同 UTC 开球日的到期场次共用一次列表查询（按页读取）。 |
| 仍在比赛 | 开球后 48 小时内每 15 分钟复查，之后每天复查。延期或取消时停止轮询原场。 |
| 确认完赛 | 读取单场详情，保存评分依据，计算评分并发布榜单。同一场完赛比赛修正开球时间时保留已有评分，取得有效新数据后更新。 |
| 首采后 6 小时 | 再取详情，处理供应商更正。仍缺评分依据时，首采后 24 小时补查一次。网络临时失败延后 15 分钟重试。 |

例如凌晨 03:00 开球，05:05 首查，仍在进行则 05:20 再查。若 05:20 确认完赛并取得详情，11:20 复查，必要时次日 05:20 最后补查。

在项目目录运行以下命令启动常驻采集器。

```sh
npm run collect:watch
```

常驻进程每五分钟查看本地待办，在两次扫描之间有比赛到点时提前唤醒。`npm run collect` 只运行一轮。进程重启会接续 SQLite 任务。两个进程同时启动时，数据库锁确保只有一个执行采集。数据库默认存放在 `data/collector/`，可用 `RATE90_STATE_DIR` 指定持久目录。`BSD_API_TOKEN` 从环境或项目下的 `.env.local` 读取。

BSD 返回 429 时，采集器对全部联赛暂停请求，至少等待 15 分钟，并遵守更长的 Retry-After。采集快照从索引移除后保留 7 天。

历史回填使用比赛 ID 建立持久队列，每批最多补 8 场，优先处理新完赛比赛。取得完整过程数据的历史比赛直接发布，字段不足的次日再查。

Linux 用户服务模板在 [rate90-collector.service](../deploy/rate90-collector.service)。模板使用 `~/Rate90` 和系统 PATH 中的 Node。项目路径不同时修改 `WorkingDirectory`，通过 nvm 安装 Node 时把 `ExecStart` 中的 Node 换为实际绝对路径。以下命令安装并启动用户服务。

```sh
install -Dm644 deploy/rate90-collector.service ~/.config/systemd/user/rate90-collector.service
systemctl --user daemon-reload
systemctl --user enable --now rate90-collector.service
journalctl --user -u rate90-collector.service -f
```

静态页面和采集器应共用 `public/ui/data/`。采集器先发布按内容生成文件名的比赛日详情，再原子替换 `collected-index.js`。独立静态托管时，发布流程需要把这两部分同步到托管站点。逐脚记录、SQLite 队列和凭据仅保存在采集机器上。

## 评分算法 rate90-1.1.0

评分使用常规时间和上下半场补时。加时与点球大战另计。逐脚 xG 缺失或候选机会缺少球队归属时，返回 `rating: null`。乌龙球参与比分进程与精彩瞬间计数，进攻射门量和 xG 只计实际起脚。

逐脚评分对 0.10 到 0.20 之间的 xG 门槛取均匀平均。实现按本场实际射门 xG 切分区间，分别计算六项分值，再按区间长度加权。普通射门 xG 为 0.10、0.15、0.20 时，分别参与 0%、50%、100% 的计算。进球、中柱和 xGOT ≥ 0.35 的射门始终作为一次机会。标签以及旧版 15 分钟汇总继续使用 0.15 的统计口径。

| 维度 | 权重 | 计算 |
| --- | ---: | --- |
| 进攻威胁 | 25 | 有效 xG = 全场 xG − 0.5 × 明确标记的点球 xG。70% 看总量（4 封顶），30% 看每脚均值（0.18 封顶）。 |
| 进攻节奏 | 15 | 55% 看射门数（32 封顶），45% 看关键机会数（10 封顶）。 |
| 看点持续性 | 20 | 60% 看机会前后各 5 分钟覆盖的实际比赛分钟占比，重叠只计一次。其余时段若合格攻势曲线连续至少 3 分钟同向且绝对值 ≥ 40，每分钟计 0.25。40% 看 1 − 最长机会间隔 / 比赛时长，包括开场和终场两端。比赛时长由常规 90 分钟及两半场各自已宣布或观测到的最大补时确定，中场休息不计。 |
| 双方对抗 | 15 | 机会较少一方达到 3 次时数量系数满分。均衡度取该方机会数的两倍除以总机会数；同段互有威胁的窗口 3 段封顶。两者按 70% 和 30% 混合；有合格攻势曲线时，攻势换边另占该维度的 20%（5 次封顶）。 |
| 射门与扑救看点 | 10 | 进球、中柱、高难度扑救各计 1。射正后 xGOT ≥ 0.35 且比起脚 xG 高至少 0.25，该脚增加 0.25 的精彩度。累计 6 封顶。 |
| 比赛悬念 | 15 | 65% 看平局或一球差时间占比。35% 取扳平与反超、末段扳平或领先进球、末段关键机会三者的最大值。76 分钟起的机会按起脚前比分判断，进攻方打平或落后一球时计入；3 次封顶，再乘末段比分接近的时间占比。整项乘全场机会活跃系数（4 次封顶）。 |

同一分钟内按补时与可用秒数排先后；时间仍有歧义时，仅当所有可能的起脚前比分均符合条件才计末段机会。每一项按百分制保留一位小数，六项相加后转为十分制并四舍五入至一位。8.0 分起建议看全场，4.5 至 7.9 分建议看集锦，低于 4.5 分可跳过。

### 证据口径

- 汇总样本保留了分段射门、分段关键机会、双方机会、总 xG、有值的 xGOT 数及高难度扑救数。对抗按双方机会总数计算，精彩度按有记录的进球和高难度扑救估算，上限为关键机会数。缺少这两项依据时，精彩度按关键机会数估算（12 次封顶）。xGOT 有值次数只用于判断覆盖。
- 逐脚数据提供射正次数及 xGOT 覆盖。扑救的 xGOT ≥ 0.35 计高难度扑救。缺少 xGOT 时，xG ≥ 0.35 的被扑射门单列为机会质量代理。供应商补估和来源未知的 xG 分别记录数量。
- 逐球比分优先由进球事件重建，也可用射门结果重建。归属、排序及两队最终进球数均须可核对。逐脚场次缺少可信比分进程时，只使用已知终场分差估计基础悬念。只有六段汇总的历史样本沿用原分段持续性和末段机会估算。
- 后端分析的 `weightedChanceCount` 为连续口径的机会数；`longestGapMinutes` 和 `lateResultChances` 分别为按区间加权的最长间隔和末段可改变结果的机会数。只有汇总数据时，后两项为空。
- 压力曲线至少覆盖 72 个常规时间分钟，每个 5 分钟段至少覆盖 3 分钟。相邻两段的平均压力方向相反，且各自绝对值达到全场平均绝对压力的一半，计一次换边。
- 球队、联赛、轮次用于匹配与筛选。当前赛季样本没有逐次传递、战术指令和失误归因。

### 公开详情与离线复算

| 详情字段 | 可用内容 |
| --- | --- |
| `lineups.home`、`lineups.away` | `formation`、`coach`、首发 `players`、替补 `substitutes`。球员包含名字、号码、位置及队长标记 |
| `stats` | `shots`、`shotsOnTarget`、`xg`、`possession`、`crosses`、`tackles`、`distanceKm`，每项分别列主客队值，缺测为 `null` |
| `pressure` | 常规时间逐分钟攻势，正值代表主队，负值代表客队，缺测分钟为 `null` |
| `events` | 换人及黄牌、两黄变红、红牌，带主客队、分钟与补时 |

`npm run verify:round` 从本轮 66 份原始响应复算评分。`npm run build:snapshot` 使用同一算法生成公开索引、列表与按日详情。评分分项可在后端 `rateMatch(match).analysis.components` 中复核。[当前数据覆盖](../README.md#当前数据)
